Data & Decisions

Overview (5 min): Move fast — set up the throughline: information design is a decision-support discipline, not a reporting exercise.
Opening story

Meridian's execs meet
every Monday.

  • A 47-slide data pack, every single week
  • Revenue, churn, NPS, pipeline, headcount, tickets — everything
  • Every function represented, every metric defended
  • The meeting still ends the same way
  • Someone says "let's just go with gut on this one"

More data isn't the fix. Past a point, it's the problem.

03
Story (5 min): Read "47 slides" flat — let the absurdity land on its own. Don't editorialise yet, the reframe comes in the next two concept slides.
What leaders actually need

Not more data.
Better signal.

  • Signal — the number that actually moves the decision
  • Context — compared to what: last week, plan, competitor
  • Confidence — how sure are we, and why
  • Anomaly detection — what changed, what's the outlier
  • A clear "so what?" — what should I do differently, now

A dashboard that shows everything helps no one decide anything.

04
Concept (8 min): This list is the spine of the module — participants should be able to name it back by the end of the day.
Dashboard design principles

Every dashboard needs
a hierarchy.

  • Hierarchy — one primary metric, everything else supports it
  • Primary metric — the number the decision actually hangs on
  • Supporting metrics — three, maybe four, never more
  • Trends — direction matters more than the point-in-time number
  • Anomalies — flag what's unusual, don't bury it in a grid
  • Clear labels — no acronyms without definitions, no ambiguous axes

Data quality as UX

Trust is designed.

  • Recency — when was this last updated, and does it matter
  • Methodology — how was this number actually calculated
  • Uncertainty — is this a precise count or a rough estimate
  • Trust signals — small, consistent cues that say "you can rely on this"
  • Data lineage — where this number came from, who owns it

People don't distrust bad data. They distrust data with no visible source.

07
Concept (7 min): Trust is designed, not assumed. If the room needs the connective tissue, tie this back to Module 01's "design = judgment."
Activity 01 · 15 min

Critique the Dashboard

Activity 0115 min

Bring a real dashboard — yours, a client's, or the example provided. Critique it against what you just learned.

  1. Identify the noise — what's on here that doesn't drive a decision
  2. Identify the signal — what actually should drive one
  3. Identify the missing context — what you'd need to trust this number
  4. Debrief: name the one number that actually matters for the decision
Activity 01 (15 min) — Watch for: participants trying to add metrics instead of removing them. If someone's answer to "missing context" turns into "we should add a filter for that," redirect — this is a subtraction exercise, not an addition one.
AI-generated insights

A model flagging
something isn't enough.

  • Design for confidence — show the model's certainty, not just the number
  • Design for reasoning — one line on why the system flagged this
  • Design for the "so what?" layer — the insight isn't the output, the action is
  • Design for actionability — every AI insight should suggest a next step, not just state a fact

An AI insight without a "so what?" is just more noise with better formatting.

09
Concept (7 min): This is the bridge to Module 12 — judgment doesn't disappear because the system generated the insight. Someone still has to decide what it means.
Quick hit · 5 min
"

What metric does your leadership team
consistently misread — and why?

Look for the pattern: is it the metric, or how it's presented?

Quick Hit 02 (5 min): Take 3–4 answers from the room. Common culprits: vanity metrics shown without context, or trailing indicators read as leading ones.
Activity 02 · 15 min

Redesign a Panel

Activity 0215 min

Take one panel from the dashboard you critiqued. Redesign it to support exactly one decision.

  1. Name the decision — what will someone actually do differently because of this panel
  2. Name the signal — the one metric that should lead
  3. Name the context — what it needs to be compared against to mean anything
  4. Cut everything that doesn't serve the decision
Activity 02 (15 min) — Do not redesign it for them. Ask questions: "What would someone do differently if this number went up? Down?" If they can't answer, the panel isn't done yet.
Synthesis · 10 min

The real job of information design.

Showing everything is not the same as showing what matters.
Trust is built through context, not volume.
The best dashboard answers one question well.
